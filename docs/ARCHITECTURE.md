# Архитектура Tweet Translator

Этот документ предназначен для разработчиков. Пользовательская установка и настройка описаны в основном [README](../README.md).

## Общая схема

Расширение состоит из четырёх независимых частей:

1. Платформенные адаптеры находят Twitter/X-триггер и открытый popup.
2. Content script управляет общим жизненным циклом оригинала и перевода.
3. Translation layer переводит текст, повторяет временно неудачные запросы и кэширует результат.
4. Overlay клонирует исходную карточку, заменяет текст и синхронизирует прокрутку.

Разделение позволяет менять поддержку одной платформы, не затрагивая остальные.

## Структура проекта

```text
src/
  background/          запросы к бесплатному Google endpoint
  content/             жизненный цикл popup и координация компонентов
  options/             страница настроек
  platforms/
    axiom/             изолированная интеграция Axiom
    gmgn/              изолированная интеграция GMGN
    padre/             изолированная интеграция Padre
    shared/            общая структурная логика Twitter popup
  shared/              настройки и DOM-path
  translation/         провайдеры, timeout, retry, cache
  ui/                  клонирование, позиционирование и scroll sync
_locales/              английская и русская локализация Chrome
tests/
  unit/                детекторы и независимая логика
  e2e/                 загрузка собранного MV3-расширения
```

## Платформенные адаптеры

Каждая платформа реализует `PlatformAdapter` и хранит собственные selectors и detector. Адаптер отвечает только за:

- поиск элемента, который открывает Twitter popup;
- определение корня popup и визуальной карточки;
- поиск переводимых текстовых блоков;
- поиск прокручиваемой области.

Общий content script не знает DOM Axiom или GMGN. Новый сайт добавляется отдельным адаптером и регистрируется в `src/platforms/registry.ts`.

Детекторы не должны зависеть от сгенерированных Tailwind-классов. Предпочтительны стабильные признаки: URL статуса X, семантика элементов, вычисленные стили и структура portal-root.

## Жизненный цикл popup

Content script слушает наведение, запоминает активный триггер и просит текущий адаптер найти popup. После обнаружения он:

1. создаёт overlay;
2. запускает перевод всех найденных текстовых блоков;
3. следит за видимостью и положением исходного popup;
4. закрывает overlay одновременно с оригиналом;
5. сохраняет возможность повторного наведения на тот же триггер.

Внутренние ссылки оригинального popup не считаются новым триггером. Пока оригинал открыт, переход курсора между его элементами не закрывает перевод.

Оригинал, прозрачный мост через визуальный зазор и overlay образуют общее hover-пространство. Выход оригинального popup в сторону overlay перехватывается, поэтому сайт не закрывает карточку при переходе курсора. После ухода за пределы обеих карточек исходное событие закрытия восстанавливается.

## Клонирование интерфейса

`TranslationOverlay` клонирует визуальную карточку целиком. Благодаря этому сохраняются:

- изображения и аватары;
- иконки и счётчики;
- размеры, цвета, шрифты и отступы сайта;
- вложенные цитируемые твиты.

Меняются только определённые адаптером текстовые узлы. Формы и клики внутри клона блокируются, а медиа не запускается автоматически.

Интерактивной остаётся только служебная метка перевода: она копирует все переведённые текстовые блоки в буфер обмена.

Положение пересчитывается относительно фактического размера оригинала на каждом animation frame. Это учитывает анимацию появления и масштабирование сайта.

## Синхронизация прокрутки

Исходный и клонированный scroll-контейнеры связаны в обе стороны. Синхронизируется не абсолютное число пикселей, а относительный прогресс:

```text
progress = scrollTop / (scrollHeight - clientHeight)
```

Так конец оригинала соответствует концу перевода, даже если перевод заметно длиннее.

## Перевод

Цепочка провайдеров создаётся фабрикой `src/translation/provider-factory.ts`: Google всегда
идёт первым, затем только явно включённые MyMemory и proxy. `SequentialTranslationProvider`
не запускает гонку запросов, останавливается на `AbortError` и временно пропускает сервис
после серии ошибок. MyMemory вызывается через background worker сегментами не более 500
байт UTF-8.

`Translator` защищает структурные и криптографические фрагменты, дедуплицирует одновременные
запросы и хранит успешные результаты в ограниченном LRU-кэше. Ключ включает идентификатор
цепочки, целевой язык и нормализованный исходный текст.

`Translator` не зависит от конкретного сервиса. Он отвечает за:

- нормализацию текста;
- кэш по языку и содержимому;
- объединение одинаковых параллельных запросов;
- timeout;
- повторные попытки с небольшой задержкой.

Доступны два провайдера:

- `google-free` — запрос через background service worker к неофициальному Google endpoint;
- `proxy` — пользовательский HTTPS backend.

Формат запроса proxy:

```json
{ "text": "source text", "targetLanguage": "ru" }
```

Формат ответа:

```json
{ "text": "перевод", "detectedLanguage": "en" }
```

Сервер должен ограничивать CORS, размер тела и частоту запросов. Секретные ключи следует хранить только на сервере. Origin proxy необходимо явно добавить в `host_permissions`.

## Локализация

Строки расширения находятся в `_locales/en/messages.json` и `_locales/ru/messages.json`. `chrome.i18n` выбирает язык по настройке Chrome. Английский указан как `default_locale`.

Список целевых языков хранится в `src/options/languages.ts`. Их названия формируются через `Intl.DisplayNames` на языке интерфейса браузера. Значение по умолчанию задаётся в `src/shared/settings.ts` и отдельно дублируется внутри content entrypoint, чтобы сборщик не создавал недопустимый ESM-импорт в `content.js`.

## Ограничение сборки MV3

Chrome загружает `content.js` как обычный manifest content script. В нём не должно быть верхнеуровневых ESM-импортов.

Не следует выносить runtime-код, одновременно используемый options page и content script, в общий модуль без проверки результата Rollup. После сборки необходимо убедиться, что `extension/content.js` автономен.

## Добавление новой платформы

1. Создайте отдельную директорию в `src/platforms`.
2. Реализуйте selectors, detector и `PlatformAdapter`.
3. Зарегистрируйте адаптер в registry.
4. Добавьте только необходимые `matches` и `host_permissions`.
5. Добавьте unit-тесты на сохранённой обезличенной DOM-структуре.
6. Проверьте повторное наведение, цитируемый твит, длинный перевод и scroll sync.
7. Проверьте текущий сайт в живом Chrome.

Изменения одной платформы не должны добавлять её селекторы или исключения в адаптер другой платформы.

## Проверки перед публикацией

```bash
npm run lint
npm run typecheck
npm run test
npm run build
npm run test:e2e
```

Также нужно проверить:

- отсутствие ESM-импорта в `extension/content.js`;
- наличие `_locales` в `extension`;
- первый и повторный hover на каждой платформе;
- закрытие перевода одновременно с оригиналом;
- синхронную прокрутку при более длинном переводе;
- работу после SPA-навигации.
