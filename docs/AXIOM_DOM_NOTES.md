# Axiom DOM notes

## Подтверждённая стратегия

Реализация проверена в текущей авторизованной сессии Axiom через Chrome DevTools Protocol и опирается на структурные признаки, а не на сгенерированные CSS-классы.

- Триггер: ближайшая ссылка на статус `x.com`/`twitter.com`.
- Popup: подтверждённый portal-root с `position: fixed`, `pointer-events` и высоким `z-index`; семантические `tooltip/dialog/react-tweet` остаются совместимыми fallback-вариантами.
- Контент: визуальный корень выбирается по фактическому размеру относительно lifecycle-root, без предположения о конкретном номере дочернего узла.
- Текст: читаемые широкие блоки определяются по геометрии и вычисленному размеру шрифта; основной и цитируемый твиты переводятся отдельно.
- UI: полная DOM-копия popup в light DOM; переводимые узлы и скроллер сопоставляются с клоном стабильными DOM-путями.
- Скролл: исходная карточка и копия синхронизируются в обе стороны по относительному прогрессу, а не по одинаковому `scrollTop`.
- Lifecycle: делегированный `pointerover`, MutationObserver родителя popup и проверка видимости через animation frame. Перевод удаляется в ту же мутацию, что и оригинал.

Подход поддерживает React Portal и повторное использование/виртуализацию DOM-узлов. Общий lifecycle и UI не содержат Axiom-селекторов; они сосредоточены в `src/platforms/axiom`. Код не читает React internals, cookies или storage сайта.

## Что подтвердить вручную

После заметного обновления сайта проверить несколько коротких и длинных карточек, повторный hover, изображения и достижение конца обеих прокруток. Если структура изменилась, корректируется только Axiom-адаптер и его fixture-тесты.
